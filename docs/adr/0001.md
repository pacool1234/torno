# ADR-0001: Ports and adapters, with an event stream

- **Status:** Accepted
- **Date:** 2026-10-02

## Context

torno talks to several things that change independently of its logic: model providers with different protocols, a filesystem, a shell, a user interface, storage. Some of these are slow, costly or non-deterministic (model APIs), which makes code that calls them directly hard to test.

The same agent must run in at least three ways: an interactive REPL, a later TUI, and a headless mode driven by an eval harness.

## Decision

Use **ports and adapters** (hexagonal architecture):

- `src/core/` holds the logic: agent loop, conversation model, tool registry, permission policy, context management. It performs no I/O and **never imports from `src/adapters/`**.
- `src/core/ports/` holds the interfaces the core needs from the outside world (e.g. `ModelProvider`, `Approver`, `SessionStore`, `Telemetry`, `Clock`). The core owns these interfaces.
- `src/adapters/` holds implementations of those ports (providers, tools, UI, storage).
- `src/main.ts` is the **composition root**: the only place that creates adapters and wires them into the core.

The agent loop **emits events** (text delta, tool start/end, permission request, usage, error) and never prints. Every UI — REPL, TUI, headless JSON — is a consumer of the same event stream.

## Alternatives considered

- **Plain modules calling APIs directly.** Fastest to start, but the loop becomes untestable without network access, and every new provider or UI touches core logic.
- **An agent framework (LangChain, Vercel AI SDK, etc.).** Solves the plumbing, which is precisely the part this project exists to learn. Also hides the protocol details the eval project needs to control.
- **Classic layered architecture (UI → service → data).** Dependencies point downwards towards infrastructure, so the core ends up depending on concrete providers. Ports and adapters inverts that.

## Consequences

- **Good:** the loop is testable with a fake provider, deterministically and for free. Providers and UIs can be added without editing the core. The eval harness gets headless mode almost for free.
- **Cost:** more files and indirection than a straight script.
- **Rule against over-abstraction:** create a port only for something that genuinely varies or is hard to test (models, filesystem, shell, clock, UI, storage). Utilities such as path manipulation are not ports. The reviewer should flag unjustified ports.
- **Enforcement:** add a lint rule or test that fails if anything in `src/core/` imports from `src/adapters/`.
