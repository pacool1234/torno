# ADR-0008: A hard cap on tool results

- **Status:** Accepted
- **Date:** 2026-10-06
- **Amends:** ADR-0007

## Context

ADR-0007 deferred context management, and `VISION.md` listed "truncation of large tool outputs" under Later. The review of the `agent-loop` change found a concrete failure that this leaves open in week 1:

1. The model runs `bash` with `cat build.log` on a 4 MB log (about a million tokens).
2. The result goes into the conversation unchanged. The next request exceeds the model's context window and fails with `invalid_request`.
3. The result stays in the conversation, so every later message fails the same way. The session is unusable until the REPL restarts, and each attempt may cost input tokens.

The week-1 demo runs `bash` in a real repository, so one large output is likely, not hypothetical.

## Decision

The agent loop caps every tool result at **30,000 characters** (roughly 7,500 tokens). A longer result keeps its first 15,000 and its last 15,000 characters, with a line in between saying how many characters were left out. The cut never splits a character encoded as a UTF-16 surrogate pair (most emoji).

- **In the loop, not in each tool:** it's the one place every result passes through, so no tool, present or future, can bypass it.
- **Head and tail, not just the head:** a build or test log usually ends with the part that matters (the error, the summary).
- **Characters, not tokens:** counting tokens needs the model's tokenizer; a character cap is cheap, predictable and good enough for a safety limit.
- **Fixed, not configurable:** one constant until there's a reason to tune it.

Smarter context management (per-tool truncation, compaction, summarising old turns) stays deferred, as ADR-0007 decided.

## Alternatives considered

- **Keep the deferral and document the risk.** No code, but the demo's most likely failure would end the session.
- **Each tool truncates its own output.** Tools can be smarter (`read_file` could show a line range), but every tool must remember to do it, and a forgotten one breaks the session. Tools may still add their own limits later; the loop's cap stays as the backstop.
- **Cap by tokens.** More precise, but needs a tokenizer per model, which torno doesn't have.

## Consequences

- A result's middle can be lost; the model sees the note and can ask for less (e.g. `grep`, `tail`, a line range).
- The REPL shows the capped result, so the user sees what the model saw.
- `VISION.md`: "truncation of large tool outputs" moves out of Later, which keeps only the smarter forms.
