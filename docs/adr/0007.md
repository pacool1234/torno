# ADR-0007: Scope and working method for a two-week timeline

- **Status:** Accepted
- **Date:** 2026-10-05
- **Amends:** ADR-0003, ADR-0004, ADR-0005

## Context

torno was planned as an open-ended learning project in five phases (`VISION.md`). On 2026-10-05 the available time shrank to one or two weeks, shared with a second portfolio project (RAG) that has priority.

The first week alone must produce something worth showing: a working agent that a real model drives through a small coding task, with a README and a demo. A second week is likely but not guaranteed.

The same constraint already changed who writes the code (`AGENTS.md`, rule change of 2026-10-05). This ADR records the scope and process changes that follow from it.

## Decision

### Scope

**Week 1: the minimum worth showing.**

1. Finish the `model-and-provider-port` change, with a smaller contract suite (see below).
2. The Anthropic-protocol adapter, over raw HTTP as ADR-0003 decided: event-stream parsing, tool-call assembly from partial JSON, error mapping, cancellation. Developed against Ollama, validated against about 5 recorded responses from Claude Haiku.
3. The agent loop in `src/core/`: emits events, enforces a turn limit and `max_tokens`, runs tool calls sequentially, and answers all of a turn's tool calls in one user message. Tested with the scripted provider.
4. Tools `read_file`, `write_file`, `edit_file` and `bash`; path confinement (ADR-0005 level 2); a permission prompt for every write, edit and `bash` call (level 1); a line-based REPL where Ctrl-C cancels the current response; wiring in `src/main.ts`.
5. A README with a demo recording.

**Week 2 (optional), in priority order.**

1. Token usage and cost telemetry, using a price table.
2. Headless mode (`-p "task" --json`) and one JSONL trajectory file per run.
3. A mini evaluation: about 5 small tasks × 2 models, results in the README.
4. Prompt caching with one explicit breakpoint.

**Moved to "Later"** (not started without a new ADR):

- The OpenAI-compatible adapter (amends ADR-0003: one real adapter instead of two in this timeline).
- The retry wrapper (design D5 of `model-and-provider-port`). The retryable classification stays in the port: it's one small function, and the wrapper can use it later.
- Context management beyond prompt caching: compaction, sessions, project memory.
- Everything in the former Phase 5: subagents, MCP, TUI, hooks, plan mode.
- The permission allowlist. Every write, edit and `bash` call simply asks.
- Running a turn's tool calls in parallel.

### Contract suite

The `model-provider` contract suite covers four situations instead of five: text-only answer, text then tool call, failure after some text, never finishing until cancelled. "Failure before the first event" is dropped from the suite because it mattered mainly for the retry wrapper, which is deferred. The scenario stays in the spec and is tested in the adapter's own tests.

### Process

- New openspec changes get a proposal, specs and tasks. A `design.md` is written only when there is a real decision with alternatives.
- The human reviews every task group. The AI runs a full `REVIEW.md` review once per change, not once per group.
- Tests are written by the AI, together with the code, and proven able to fail (amends ADR-0004, which said the human writes all tests). Test-first for the core still applies.

### Sandboxing for the mini evaluation

The mini evaluation runs model-generated `bash` commands with no human approving them. ADR-0005 planned a container (level 4) for eval runs; that is deferred. Instead, each run happens in a fresh temporary directory, with a headless policy that allows only the tools the task needs, against small trusted task repos (amends ADR-0005).

## Alternatives considered

- **Keep the original five-phase plan.** Nothing worth showing would exist after two weeks: the first phase alone was planned to end before the agent loop exists.
- **Use the official Anthropic SDK to save a day.** Rejected: hand-written streaming and tool-call assembly is the main thing that sets this project apart from SDK wrappers.
- **Drop openspec entirely.** Faster, but loses the written trail of specs and decisions, which is part of what the portfolio shows.
- **Second adapter instead of the evaluation in week 2.** Would prove the port abstracts providers (ADR-0003's reason for two adapters), but adds no visible capability. The evaluation produces real numbers and is closer to the skills an AI engineering role asks for.

## Consequences

- **Good:** a demoable agent after one week; real measurements after two.
- **The port is validated by one real adapter only.** ADR-0003 warned that a port shaped by a single implementation tends to copy it. Accepted risk: the scripted provider and the contract suite are the only second check until the OpenAI-compatible adapter lands.
- **The mini evaluation runs without isolation.** A model can run any shell command inside the temporary directory, and `bash` can reach outside it. Only small, trusted task repos are used, and this limitation is stated next to the results.
- **No retries.** A rate-limit or overload error ends the turn with a clear message; the user retries by hand.
- `VISION.md` is rewritten around this plan, and the deferred items are listed under "Later" so they aren't forgotten.
